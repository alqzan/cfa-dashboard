# لوحة متابعة CFA — المستوى الثاني — v6 (CFA Personal Coach)

لوحة تتبّع مذاكرة لمنهج CFA Level II 2026، ثابتة بالكامل (Static)، تعمل من متصفح واحد بدون
أي backend، مع طبقة تدريب شخصية (مراحل القراءة، دفتر الأخطاء، محرك نقاط الضعف، جاهزية مبنية
على أدلة فعلية) ومزامنة سحابية اختيارية عبر Firebase.

## تشغيل المشروع محلياً

لا يوجد build step. أي سيرفر ثابت يكفي، مثلاً:

```bash
python3 -m http.server 8080
# افتح http://localhost:8080/index.html
```

أو ببساطة افتح `index.html` مباشرة من متصفح Chrome/Edge/Safari (بعض ميزات الحفظ الدائم تحتاج
تحميل الصفحة عبر رابط `http://` أو `https://`، وليس مباشرة من نظام الملفات `file://` — راجع
تنبيه Safari/iPad داخل الصفحة نفسها لو ظهر).

## بنية الملفات

```
index.html                          الهيكل + عناصر الواجهة فقط
assets/css/app.css                  كل التنسيقات
assets/js/readiness.js              معادلة الجاهزية (25/15/25/15/20) — ملف مستقل قابل للتعديل
assets/js/app.js                    كل منطق التطبيق: الحالة، الـmigration، الرسم، دفتر الأخطاء، إلخ
assets/js/firebase-sync.js          طبقة مزامنة Firebase (اختيارية، type=module)
assets/js/firebase-config.example.js  نموذج إعدادات Firebase — انسخه إلى firebase-config.js
firestore.rules                     قواعد أمان Firestore (كل مستخدم يرى بياناته فقط)
sw.js                                Service Worker (عمل بدون إنترنت + تحديث آمن بدون مسح بيانات)
manifest.json                       بيانات PWA (أيقونة الشاشة الرئيسية)
tests/*.test.mjs                    اختبارات آلية (Node، بدون متصفح) — شغّلها بـ npm test
.github/workflows/deploy-pages.yml  نشر GitHub Pages تلقائي + يدوي
FIREBASE_SETUP.md                   خطوات إعداد Firebase Console (يدوية بالكامل)
backup/v5-snapshot/                 نسخة كاملة من index.html كما كانت قبل ترقية v6
```

كل شيء ES-modules/plain-script حسب الحاجة، بدون أي build tool أو bundler — المشروع يبقى Static
وقابلاً للنشر مباشرة على GitHub Pages.

## تشغيل الاختبارات

```bash
npm test
```

يشغّل كل ملفات `tests/*.test.mjs` (migration v5→v6، معادلة الجاهزية، دمج المزامنة). لا يحتاج
أي اتصال شبكي أو مشروع Firebase حقيقي — كلها اختبارات وحدة (unit tests) على دوال JS صرفة.

## النشر على GitHub Pages

### تلقائياً

كل `push` أو merge إلى `main` يشغّل `.github/workflows/deploy-pages.yml`:
checkout → التحقق من وجود الملفات الأساسية → `npm test` → تجهيز مجلد النشر (بدون build حقيقي،
مجرد نسخ الملفات الثابتة ما عدا `firebase-config.js` إن وُجد محلياً) → رفعه كـ Pages artifact →
نشره. لو فشلت الاختبارات، لا يحدث نشر.

### يدوياً (Run workflow)

من تبويب **Actions** في المستودع على GitHub → اختر **Deploy to GitHub Pages** من القائمة
الجانبية → زر **Run workflow** أعلى يمين القائمة → اختر الفرع (`main` عادة) → **Run workflow**.

### تفعيل GitHub Pages أول مرة (خطوة يدوية عليك)

من **Settings → Pages** في المستودع: تحت **Build and deployment → Source** اختر
**GitHub Actions** (وليس "Deploy from a branch"). هذه خطوة تُعمل مرة واحدة فقط.

## إعداد Firebase (اختياري تماماً)

المزامنة السحابية اختيارية بالكامل — اللوحة تعمل محلياً 100% بدونها. الخطوات كاملة (إنشاء
مشروع، Web App، تفعيل Email/Password Authentication، إنشاء Firestore، نشر القواعد، وملء
`assets/js/firebase-config.js`) موثّقة في **[FIREBASE_SETUP.md](FIREBASE_SETUP.md)** — كلها
تحتاج وصولك أنت لـ Firebase Console، لا يمكن تنفيذها من هنا.

بإيجاز شديد بعد إنشاء المشروع:
```bash
cp assets/js/firebase-config.example.js assets/js/firebase-config.js
# ثم املأ القيم الست من إعدادات مشروعك في firebase-config.js (غير متتبَّع في Git)
```
بعدها يظهر قسم "مزامنة السحابة" في الصفحة تلقائياً.

## اختبار المزامنة بين جهازين

بعد إعداد Firebase: افتح اللوحة في متصفحين/جهازين، سجّل الدخول بنفس الحساب في الاثنين، عدّل
شيئاً في الأول واضغط "مزامنة الآن"، ثم اضغط "مزامنة الآن" في الثاني — يجب أن يظهر نفس التعديل.
تفاصيل أكثر (بما فيها اختبار التعارض المتعمّد) في نهاية FIREBASE_SETUP.md.

## الرجوع إلى نسخة سابقة

- **عبر Git:** كل مرحلة من الترقية دُفعت كـ commit منفصل وواضح على فرع
  `claude/cfa-coach-v6-upgrade-yxbzvu` — يمكن عمل `git revert` أو `git checkout` لأي commit
  سابق، أو الرجوع الكامل لآخر commit على `main` قبل الدمج.
- **نسخة v5 الكاملة:** محفوظة كما هي (بدون أي تعديل) في `backup/v5-snapshot/index.html`.
- **بياناتك الشخصية:** الـmigration من v5 إلى v6 لا يحذف شيئاً أبداً، ويأخذ نسخة احتياطية
  تلقائية من بياناتك الخام قبل أول تشغيل لها (مفتاح `cfa_l2_dash_pre_v6_backup` في
  localStorage) — حتى لو فشل الـmigration لأي سبب، بياناتك الأصلية تبقى كما هي دون أي كتابة
  فوقها.

## أخذ نسخة احتياطية من بياناتك

من داخل اللوحة نفسها: زر **"تصدير نسخة احتياطية"** يحفظ ملف JSON، أو **"نسخ للحافظة"** لنسخ
نفس المحتوى مباشرة. اللوحة أيضاً تأخذ لقطة أسبوعية تلقائية داخل المتصفح (زر **"نسخ أسبوعية
محفوظة"** لمراجعتها أو استعادتها). كل هذا كان موجوداً في v5 ولم يتغيّر.

## ملخّص ترقية v5 → v6

- **Migration حقيقي، وليس Reset:** `migrate()` في `app.js` تتحقق من رقم النسخة وتضيف كل حقول
  v6 الجديدة (المراحل، خريطة المصادر، Pre-Question Brief، دفتر الأخطاء، إلخ) بشكل إضافي بحت —
  لا تُحذف ولا تُعاد تسمية أي هوية بيانات موجودة (id قراءة، مراجعة، محاكاة، جلسة، يوم...).
- **منهج 2026:** 42 قراءة رسمية، مُتتبَّعة داخل اللوحة كـ45 وحدة دراسة. تغيير Machine Learning
  LOS E (حذف Neural Networks/Deep Learning/Reinforcement Learning) مُطبَّق كاستبعاد جزئي من
  الحساب، وليس حذفاً للقراءة كاملة.
  ملاحظة: ترقيم "Reading" الرسمي (1–42) قابل للتعديل يدوياً لكل وحدة من واجهة القراءة نفسها —
  لم أُدرجه جاهزاً بثقة كاملة لأنني لا أملك وصولاً مباشراً لمنهج CFA Institute الرسمي للتحقق من
  التجميع الدقيق؛ راجعه وعدّله حسب كتاب منهجك.
- **جاهزية مبنية على أدلة:** الصيغة القديمة (50/30/20) استُبدلت بصيغة 25/15/25/15/20 في ملف
  مستقل (`assets/js/readiness.js`)، مفصّلة في تقرير التسليم وفي تعليقات الملف نفسه.
- لا شيء من هذا يمسح بيانات المستخدم — كل الاختبارات في `tests/` تتحقق من ذلك آلياً.
